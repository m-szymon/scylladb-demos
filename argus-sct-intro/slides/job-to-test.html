A Jenkins job is a small file in the SCT repo

jenkins-pipelines/oss/longevity/longevity-10gb-3h.jenkinsfile

longevityPipeline(
  backend: 'aws',
  region: 'eu-west-1',
  test_name: 'longevity_test.LongevityTest.test_custom_time',
  test_config: 'test-cases/longevity/longevity-10gb-3h.yaml',
)

That is the whole job: which shared pipeline, which backend, which test class, which YAML. The Argus test is a page that points at this job.

What the pipeline does on every build

1

Create the run in Argus

2

Create an SCT runner VM in the cloud

3

Run hydra there with the job’s settings plus yours

4

Collect logs, clean up resources

5

Report final status to Argus and by e-mail

Steps 4 and 5 run even when the test fails or is aborted.

Shared pipelines live in vars/ in the SCT repo. More in docs/sct-pipelines.md.

The one idea: a job is a few lines that bind a pipeline template to a test class and a YAML. Argus adds a page on top of it: it discovers jobs from Jenkins, and the folder definitions file next to the jenkinsfiles tells it which plugin and which Run wizard to use. Clone in Argus goes the other way: it creates a new Jenkins job from an existing one, and the page comes with it. The numbered list is what happens when you press Run, and the runner in step 2 is why a Jenkins run has no laptop involved. The jenkinsfile snippet is simplified; open the real file if someone asks.
