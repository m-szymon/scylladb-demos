One SCT run, end to end

Runner

Hydra container. Runs the test class, drives everything over SSH.

DB cluster

ScyllaDB nodes under test, plus any sidecar the test needs.

Loaders

cassandra-stress, latte, scylla-bench, ycsb.

Monitor

Scylla Monitoring stack for the cluster and loaders.

Shared

Argus, S3 for logs, Elasticsearch, cloud account.

runner reports events, results and log archives

provision

install + configure

run workload

inject faults

collect logs

tear down

The SCT README has a generated system map per test type (docs/system-map) that shows exactly this for performance, longevity, upgrade and others.

Everything a run needs is created by the run and destroyed at the end. The runner is the only piece that runs SCT code; the rest are plain machines it drives over SSH, and the runner is also the one talking to Argus and S3. Faults are nemesis, used by longevity tests and usually skipped by performance tests. If time allows, open the interactive system map from the repo.
