Three ways to run a test

In the cloud

Argus or Jenkins

Run button in Argus, or Build with parameters in Jenkins. A runner VM is created next to the cluster. Results tracked in Argus.

Where to look while it runs: the Jenkins console first, then the Argus run as events arrive.

Needs

  • Argus and Jenkins accounts
  • Nothing on your machine

From your laptop, cloud backend

hydra run-test

Your checkout, your branch, real cloud machines. Hydra runs the test locally over public IPs, or on a runner you create in the cloud, which makes it the same as a Jenkins run.

Needs

  • Docker or Podman, AWS access via Okta
  • Cloud credentials for the backend
  • Clean up when done, it costs money

Fully local

docker or minicloud

Docker backend: cluster as containers, fastest for test logic. Minicloud: emulates EC2 and GCE APIs with KVM guests, so the real aws and gce code paths run.

Needs

  • Docker, passwordless sudo, AWS access for S3
  • Minicloud: KVM, about 22 GiB RAM, 80 GiB disk

Every way needs AWS access, even the local ones: SCT reads SSH keys and credentials from S3. Local results land in ~/sct-results/latest. Set SCT_ENABLE_ARGUS=false for local experiments.

Walk left to right. The middle column is the bridge: the same hydra command Jenkins runs, from your checkout. Without a runner, add the public-IP network config from the README table. With hydra create-runner-instance and execute-on-runner you get the Jenkins setup with your branch. Right column is where test logic gets debugged for free.
