Backends: one command, one flag

hydra run-test <module.Class.test> --backend <backend> --config test-cases/<case>.yaml

BackendWhat it isNotes
aws · gce · azure · ociPublic clouds, real VMsaws most used, gce for artifacts and upgrades. From a laptop add the public-IP network config.
xcloudScyllaDB Cloud managed clustersProvider and environment set by env vars
k8s-eks · k8s-gke · k8s-local-kindScylla Operator on KubernetesManaged clusters, or kind locally or on one VM
baremetalHosts that already exist, such as lab machinesInventory from a JSON file or the keystore
dockerContainers on your machineNot every nemesis works, see docs
minicloud (aws or gce)Emulated cloud APIs, KVM guestsSame backend code as the real cloud, no instance cost

Per-backend settings and docs: README section 3 and docs/configuration_options.md.

Do not read the table aloud. Point at the command on top: the backend is a flag plus credentials, everything else in the test stays the same. Mention that minicloud is not a backend name but a way to run the aws or gce backend locally.
